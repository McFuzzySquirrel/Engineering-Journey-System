# Problem / Intent

The repository stores Architecture Decision Records (ADRs) and Session Journeys as markdown files in `ejs-docs/`. When agents need to reference past decisions or session context, they must read all files, consuming valuable context window space. The goal was to create a SQLite-backed tool that indexes both ADR and journey metadata and content, enabling agents to efficiently query past decisions and session history via compact CLI commands instead of reading full markdown files.

# Decisions Made

- Decision: Use Python with stdlib sqlite3 for the implementation
  - Reason: Python is available in the environment, sqlite3 is built-in, no new dependencies needed
  - Impact: Tool works out of the box on any system with Python 3

- Decision: Use FTS5 full-text search with content-sync triggers
  - Reason: Enables rich text search across ADR content without manual index management
  - Impact: Agents can search for concepts, patterns, or keywords across all ADRs efficiently

- Decision: Extract adr_id from raw frontmatter text instead of YAML-parsed value
  - Reason: PyYAML (YAML 1.1) interprets zero-padded numbers as octal
  - Impact: ADR IDs preserve their original string format (e.g., "0010" not "8")

- Decision: Store tool at `scripts/adr-db.py` alongside existing utility scripts
  - Reason: Consistent with existing project structure (`scripts/` directory)
  - Impact: Natural discovery location for developers and agents

# Key Learnings

**Technical insights:**
- YAML 1.1 (PyYAML) treats zero-padded integers as octal — a common gotcha when parsing frontmatter with numeric-looking IDs
- Python f-strings consume `{1,2}` as format expressions, breaking regex quantifiers — use `{{1,2}}` in rf-strings
- SQLite FTS5 content-sync triggers provide automatic index maintenance with minimal code

**Prompting insights:**
- Clear, focused problem statements ("SQLite for ADR tracking") lead to efficient implementation sessions
- Explore sub-agents are valuable for understanding unfamiliar repositories before making changes

**Tooling insights:**
- A lightweight CLI tool can significantly reduce agent context consumption for reference lookups
- The `summary` command pattern (truncated key fields) is particularly useful for context-constrained agents

# If Repeating This Work

**Do this:**
- Test YAML parsing of zero-padded numbers early
- Test f-string regex interactions early
- Validate against real data files, not just test fixtures

**Avoid this:**
- Relying on YAML-parsed values for string identifiers with leading zeros
- Using `{n,m}` regex quantifiers inside Python f-strings without escaping

**Watch out for:**
- YAML 1.1 vs 1.2 parsing differences (PyYAML uses 1.1)
- FTS5 trigger ordering — INSERT/DELETE/UPDATE triggers must match the virtual table schema exactly

# Future Agent Guidance

**Prefer:**
- Running `python scripts/adr-db.py sync && python scripts/adr-db.py summary` at session start to load ADR context efficiently

**Avoid:**

- Skipping the `sync` step before querying (database may be stale)
