# Decisions Made

- **Decision:** Add a structured Sub-Agent Contributions section to the journey template
  - **Reason:** Sub-agents make decisions (approach choices, trade-offs) that are lost when only outcomes are recorded
  - **Impact:** Every session journey now has a place to capture per-agent decisions with rationale, alternatives, and handoffs

- **Decision:** Add SUB_AGENT_EXTRACT as a new machine extract
  - **Reason:** Downstream tools need machine-parsable sub-agent collaboration data, just as they need interaction and decision extracts
  - **Impact:** Enables automated analysis of sub-agent collaboration patterns

- **Decision:** Separate delegation recording from decision capture
  - **Reason:** Delegation events are chronological (belong in Interaction Summary), while sub-agent decisions are structured data (belong in Sub-Agent Contributions)
  - **Impact:** Clear contract for where to put what, reducing ambiguity for agents

- **Decision:** Add Sub-Agent Handoff Protocol to lifecycle patterns
  - **Reason:** Agents need explicit step-by-step guidance on how to capture sub-agent decisions and inter-agent handoffs
  - **Impact:** Agents now have a protocol with examples, not just a sequence diagram

# Key Learnings

**Technical insights:**
- Sub-agent decisions are a distinct data category from interaction events — they need their own structured section
- Inter-agent handoff chains (SA1→SA2→SA3) are a pattern worth formalizing, not just noting
- Machine extracts should mirror the journey sections — if there's a Sub-Agent Contributions section, there should be a SUB_AGENT_EXTRACT

**Prompting insights:**
- Asking sub-agents to report decisions + alternatives (not just outcomes) produces richer contribution records
- Providing prior sub-agent output as context to the next sub-agent enables informed handoff chains

**Tooling insights:**
- The existing multi-agent sequence diagram was a good foundation but needed updates to show the decision flow, not just the task flow
- Documentation-only repos benefit from code review even for markdown — it caught the delegation recording inconsistency

**Watch out for:**
- Consistency between sequence diagrams and written contracts (the review caught this)
- Ensuring the template section is instructive enough that agents know what to fill in

# Future Agent Guidance

**Prefer:**
- Recording delegation events in Interaction Summary (chronological trail)
- Recording sub-agent decisions in Sub-Agent Contributions (structured per-agent)
- Populating SUB_AGENT_EXTRACT at finalization with all sub-agent data
- Passing prior sub-agent output to subsequent sub-agents as context (handoff chain)

**Avoid:**
- Recording only sub-agent outcomes without their reasoning
- Skipping the Sub-Agent Contributions section when sub-agents were used
- Treating sub-agent decisions as less important than main agent decisions
