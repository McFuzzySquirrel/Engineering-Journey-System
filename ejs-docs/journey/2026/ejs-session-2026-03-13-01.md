# Experiments / Evidence

- Measured current instruction surface: 366 lines (copilot-instructions.md + 3 skills), ~940 words always-on, ~3,072 words total including templates
- Analyzed the journey template: 15 sections, 5 machine extracts — significant overhead for sub-agents that only need to append a few lines
- Compared copilot-instructions.md (what agents must always carry) vs. skills (loaded on demand) vs. templates (reference only)
- Key finding: the always-on instructions duplicate much of what the skills and templates already describe

  - Reason: Directly addresses the user's hypothesis while providing alternatives for comparison.
  - Impact: Informs future implementation decisions; no code changes in this session.

# Key Learnings

- The current always-on instructions (copilot-instructions.md) consume ~940 words of context in every agent interaction, even for simple tasks
- Much of the instruction content is procedural detail (how to checkpoint, how to format entries) that could be delegated to the template itself
- The journey template already contains inline guidance (section headers with descriptions) — duplicating this in instructions is redundant
- Sub-agents receive no EJS context at all in the current model — they depend entirely on the main agent to capture their work after the fact

# If Repeating This Work

Do this: Start with quantitative measurement of instruction surface area before proposing changes
Avoid this: Proposing changes without understanding how all components interact
Watch out for: The difference between "always-on" context cost (copilot-instructions.md) vs. "on-demand" cost (skills loaded when relevant)

# Future Agent Guidance

Prefer: Compact, self-contained instruction blocks that reference templates rather than embedding procedural detail
Avoid: Duplicating guidance across copilot-instructions.md, skills, and templates
