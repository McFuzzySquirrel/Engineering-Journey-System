# Decisions Made
- Decision: Recommend hooks as complementary Layer 0 (not replacement) for EJS
  - Reason: Hooks excel at guaranteed structural automation but cannot perform semantic tasks (decisions, rationale, ADR evaluation). Both layers needed.
  - Impact: Adds a reliability foundation without disrupting existing instruction/skill/agent stack.
- Decision: Recommend Option B (Lifecycle + Sub-Agent) as starting implementation
  - Reason: Best value-to-effort ratio. Closes three biggest gaps (init reliability, validation, sub-agent capture) with four scripts and low risk.
  - Impact: Medium implementation effort with high payoff for session completeness.

# Key Learnings
Technical insights: Copilot hooks are shell-script-based, receive structured JSON input, run synchronously, and only `preToolUse` can block actions. They are repo-scoped and auto-loaded from the default branch (no manual install needed).
Prompting insights: N/A — research task.
Tooling insights: The `subagentStop` hook is particularly valuable for EJS because it addresses a gap that no amount of instruction optimization can solve — sub-agents don't receive parent agent instructions.

# If Repeating This Work
Do this: Start by mapping existing automation gaps, then evaluate each hook type against those gaps. The gap-first approach produces actionable recommendations.
Avoid this: Don't assume hooks replace instructions — they are a different capability layer (deterministic vs. semantic).
Watch out for: Hook documentation is still evolving. The `subagentStop` and `agentStop` hooks have less documentation than session/tool hooks.

# Future Agent Guidance
Prefer: Using hooks for deterministic structural tasks and instructions/skills for semantic tasks. This separation of concerns is robust.
Avoid: Using `preToolUse` deny for EJS enforcement without thorough testing — agent confusion risk is real.
