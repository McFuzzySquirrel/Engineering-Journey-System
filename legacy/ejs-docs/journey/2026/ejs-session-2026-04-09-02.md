# Decisions Made
- Decision: Implement `story` as a new command, not a replacement for `summary-journeys`.
  - Reason: `summary-journeys` remains useful for its own use case (quick list with 300-char intent). `story` is richer (full intent up to 400 chars, extracted decision + learning) and serves different agent needs.
  - Impact: Agents now have two query modes: compact list vs. rich narrative.
- Decision: Use regex-based extraction helpers (`_extract_first_decision`, `_extract_first_content_line`) rather than hardcoding section content.
  - Reason: Journey content is free-form text written by humans and multiple agent types — hardcoded strings would break for variations in style.
  - Impact: Robust extraction across all 16 existing sessions with no false negatives on populated sessions.
- Decision: Reference `story` command explicitly in `copilot-instructions.md`.
  - Reason: The DB-first rule was previously vague ("Query DB before reading raw markdown files") — no specific command. Agents needed a concrete, preferred command.
  - Impact: Instructions now direct agents to `story` first, which is the most useful command for understanding session history.

# Key Learnings
Technical insights: Bold markdown in `**label:**` puts the closing `**` AFTER the colon, not before. Regex that places `(?:\*{1,2})?` before `:` misses this — it must come after. Always test regex against real data, not just expected formats.
Prompting insights: "Let's implement these" requires first auditing what's already done. Two of three recommendations were already implemented — unverified assumptions would have caused wasted effort.
Tooling insights: The `story` command output is self-validating — running it against 16 real sessions immediately reveals parsing failures as visible noise in the output.

# If Repeating This Work
Do this: Test command output against all existing journey files immediately after each change. The real data is the test suite.
Avoid this: Don't assume all recommended changes need implementing — check current state first.
Watch out for: Markdown bold formatting has multiple forms (`**text**`, `**text:**`, `*text*`) — any regex that processes journey content needs to handle bold markers in multiple positions.

# Future Agent Guidance
Prefer: `python scripts/adr-db.py story` as the first command when needing session history context. It returns the richest compact narrative.
Avoid: Reading raw journey markdown files before trying the `story` or `search` commands. The DB is always more efficient.
